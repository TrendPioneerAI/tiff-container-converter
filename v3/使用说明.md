# BigTIFF 转普通 TIFF 工具 V3.0.0

## 1. 运行环境

- Windows 10 / 11，64 位。
- 无须安装 Python、Photoshop、HxMap 或其他运行库。
- 解压整个压缩包后，双击 `BigTIFF_to_ClassicTIFF.exe`。不要只复制 EXE，`runtime` 文件夹必须与 EXE 保持在一起。
- V3 使用 Windows GUI 子系统运行，不显示命令行黑窗。

## 2. 首次授权

1. 打开软件，复制左侧显示的本机设备码。
2. 将设备码交给许可证管理员生成 `.lic` 文件。
3. 点击“安装许可证”，选择许可证文件。
4. 授权状态显示为有效后即可转换。

许可证与设备绑定；更换电脑或许可证到期后需要重新签发。

## 3. 添加文件

- “选择文件”：一次选择一个或多个 TIFF。
- “选择文件夹”：扫描文件夹中的 TIFF；勾选“递归扫描”时包含子文件夹。
- 软件只把 TIFF 文件头中版本号为 43 的 BigTIFF 加入任务，普通 TIFF 不会重复转换。
- 列表中可移除选中项或全部清空。

## 4. 两种输出方式

### 4.1 生成转换副本（默认，推荐）

选择输出/报告文件夹，软件生成 `原名-classic.tif`。源 BigTIFF 保持不变。如果不同目录中存在同名文件，软件会自动加短哈希避免重名。

### 4.2 同名无损替换原文件

勾选“同名无损替换原文件”后，软件先在原文件同目录生成临时 Classic TIFF，并完成以下验证：

- 图像块 SHA-256 一致；
- 非结构性 TIFF 元数据 SHA-256 一致；
- 输出可按 Classic TIFF 重新解析；
- 最终文件头复核为 TIFF 版本 42。

只有全部验证通过后才会以同名 Classic TIFF 替换源 BigTIFF。替换时使用同目录恢复备份和失败回滚，并恢复原文件修改时间、访问时间及可恢复的 Windows 属性。任何一步失败都会保留或恢复原文件，并在 PDF 报告中记录。

此模式会改变原文件容器，使用前仍建议保留项目级备份。Classic TIFF 使用 32 位偏移，无法表达大于约 4 GiB 或偏移超限的结构；遇到超限时软件会停止该文件，不会伪造成功结果。

## 5. 批量报告

每次点击“开始批量转换”只生成一份 PDF 报告：

- 1 个文件：1 份报告；
- 多个文件：整批 1 份报告；
- 一个文件夹：该次扫描和转换共 1 份报告。

报告包含批次结论、成功/失败数量、逐文件状态、错误原因、图像块与非结构元数据 SHA-256，以及 TIFF 容器结构变化说明。V3 不再为每个文件生成 JSON 报告。

## 6. 异常处理

- 单个文件损坏、无法读取、超出 Classic TIFF 容量、输出被占用或权限不足时，该文件标记失败，其他文件继续处理。
- 原位替换失败时，软件尝试自动回滚；如果系统同时阻止回滚，报告会给出恢复备份的完整位置，必须立即人工处理。
- 输出文件已存在时，默认不会覆盖；需要覆盖转换副本时勾选对应选项。
- 软件退出前请等待批次完成。强制结束可能留下以点号开头的临时文件，但不会把未验证文件标记为成功。

## 7. “无损”的准确含义

本工具直接复制 TIFF 中已压缩或未压缩的原始图像块，不解码、不重采样、不改变位深、不调色、不重新压缩。BigTIFF 版本 43 改为 Classic TIFF 版本 42 时，文件头、IFD、标签偏移以及 TileOffsets/StripOffsets 必须重新生成，因此整文件字节和整文件 SHA-256 必然变化；验证对象是图像块和非结构性业务元数据，而不是容器寻址字段。
